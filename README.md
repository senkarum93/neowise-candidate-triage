# Тестовое Neowise. AI-помощник для входящих заявок

Ориентир — 45–60 минут. Менеджер вводит текст заявки, получает тему и черновик ответа. Он читает результат и сам решает, что отправить клиенту.

## Запуск

В репозитории есть сервер, HTML-страница и имитатор модели. Нужен Node.js 20 или новее. Зависимостей и ключей нет.

```sh
node server.mjs
```

Откройте http://127.0.0.1:3000. Порт можно задать через переменную `PORT`.

## Тесты

```sh
node --test
```

Тесты используют встроенный `node:test`, запускают API на свободном локальном
порту и сами закрывают сервер. Отдельно запускать приложение не нужно.
Проверяются пустой и нестроковый ввод, битый JSON, все три темы, все пять
сценариев сбоя имитатора, ограничение размера запроса и таймаут провайдера,
который не реагирует на отмену. Обработчик страницы проверяется с минимальным
DOM: после успешного ответа новый сбой, сетевая ошибка или битый ответ удаляют
предыдущий черновик и показывают ручной разбор. Эти проверки не заменяют тест
в настоящем браузере.
Отдельный регрессионный тест моделирует встроенную проверку `required`:
после успешного ответа отправка полностью пустого поля вызывает `invalid`
вместо `submit`, удаляет старый черновик и не отправляет новый запрос к API.

## Поведение готового решения

- Пустой, отсутствующий или нестроковый `text`, а также битый JSON дают
  HTTP 400 и `{"status":"invalid_input"}`. Размер тела ограничен 64 КиБ;
  превышение даёт HTTP 413 с тем же статусом.
- Результат AI проверяется в `modelResult` в `server.mjs`: JSON должен содержать
  тему `delivery`, `pricing` или `other` и непустую строку `draft`.
  В ответ копируются только проверенные поля.
- Ожидание модели ограничено 300 мс. Ошибка, таймаут или неподходящий результат
  дают HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`.
  При таймауте отправляется сигнал отмены; HTTP-ответ не ждёт реакции провайдера.
- Страница показывает тему и черновик, очищает старый результат при новом
  запросе и предлагает ручной разбор при сбое. Повторная отправка заблокирована
  на время запроса, а ожидание сети на странице ограничено 5 секундами.
  Текст отображается через `textContent`.
- Выданный `mock-ai.mjs` оставлен без изменений. Зависимости и AI-ключи не нужны.

Для проверки в браузере отправьте «Когда доставка?», затем по очереди
`[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]`.
При успехе появятся тема и черновик; при каждом сбое — только сообщение
о ручном разборе. Проверьте также пустую строку и строку из пробелов.

Польза для менеджера: готовая тема и черновик сокращают время подготовки ответа,
а явный ручной разбор помогает не использовать устаревший черновик при сбое;
эффект можно измерять медианным временем от открытия заявки до готового ответа
и долей заявок, ушедших на ручной разбор.

При доработке использован OpenAI Codex для написания кода и тестов. Автоматические
проверки перечислены выше. В браузере дополнительно проверена последовательность
«успешный ответ → `[timeout]`»: черновик исчезает сразу, затем появляется ручной
разбор. Проверку можно повторить по инструкции.

## Что изменить

1. Доработайте `POST /api/triage`. Принимайте JSON с полем `text`, содержащим непустую строку. При пустом, отсутствующем, нестроковом вводе или битом JSON верните HTTP 400 и `{"status":"invalid_input"}`.
2. При корректном ответе модели верните HTTP 200 и `{"status":"ready","topic":"…","draft":"…"}`. Допустимые темы — `delivery`, `pricing`, `other`. Черновик должен быть непустой строкой. При таймауте, ошибке модели или неподходящем ответе верните HTTP 200 и `{"status":"manual_review","topic":null,"draft":null}`. Ограничьте ожидание модели 300 мс. Оставьте поведение выданного имитатора прежним.
3. Покажите на странице тему и черновик при успехе. Для `manual_review` покажите понятное сообщение менеджеру и очистите предыдущий черновик. Добавьте хотя бы один исполнимый тест для поведения при сбое и инструкцию его запуска.

Для локальной проверки имитатор принимает любой обычный текст. Метки `[timeout]`, `[error]`, `[bad-json]`, `[bad-topic]`, `[empty-draft]` включают отдельные сценарии сбоя.

## Что прислать в бота

- Ссылку на pull request и SHA проверяемого коммита. Можно использовать свой учебный репозиторий. Сохраните начальный код первым коммитом, затем откройте PR из отдельной ветки.
- Короткую инструкцию запуска и прогона теста. В описании PR ответьте, где проверяется результат AI, что происходит при сбое, какой AI вы использовали и что проверили самостоятельно. Если работали без AI, укажите это.
- Одну фразу о том, какую пользу задача даёт менеджеру и как её можно измерить.

После сдачи бот может задать один-два коротких вопроса по вашему коду. Используйте учебные данные. Если не уложились по времени, отметьте незавершённые части в PR.
